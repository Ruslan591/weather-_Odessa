# Совместная работа ChatGPT и Claude

## Цель

Этот файл является общей инструкцией для ChatGPT и Claude при работе
над репозиторием weather-_Odessa.

Цель — совместно развивать проект без потери контекста, конфликтов
и случайного изменения работающих частей системы.

---

## Репозиторий

GitHub: `Ruslan591/weather-_Odessa`

Проект включает:

- сайт прогноза погоды для Одессы;
- GitHub Pages;
- VPS Oracle Cloud;
- погодные модели Open-Meteo;
- EUMETSAT спутниковые данные;
- SYNOP и BUFR;
- фронтальный анализ;
- AI-анализ прогнозов;
- генерацию прогнозного видео;
- автоматические VPS-пайплайны.

---

## Роли AI

### ChatGPT

Основные задачи:

- анализ архитектуры проекта;
- поиск ошибок и причин проблем;
- проверка логики алгоритмов;
- анализ погодных данных;
- проверка изменений Claude;
- постановка задач;
- ведение технического контекста;
- координация работы между AI.

ChatGPT НЕ должен предполагать, что изменение работает,
без проверки кода, логов или фактического результата.

---

### Claude

Основные задачи:

- реализация изменений в коде;
- редактирование файлов;
- работа с VPS;
- выполнение команд;
- тестирование изменений;
- исправление найденных ошибок.

Перед внесением крупных изменений Claude должен:

1. Прочитать актуальные инструкции в `docs/topics/`.
2. Проверить связанные файлы.
3. Понять существующую архитектуру.
4. Не заменять работающую систему упрощённой версией.

---

## Обязательные правила

### 1. Не ломать существующий проект

Запрещено:

- переписывать большие части системы без необходимости;
- заменять существующую логику заглушками;
- удалять функции без проверки зависимостей;
- создавать дублирующие параллельные системы;
- менять структуру репозитория без причины.

Если возможен минимальный патч — использовать минимальный патч.

---

### 2. Не делать приблизительных исправлений

Нельзя исправлять проблему предположением.

Необходимо:

1. определить фактическую причину;
2. проверить входные данные;
3. проверить код;
4. проверить логи;
5. только после этого менять код.

---

### 3. После изменения обязательно проверить результат

После изменения Claude должен сообщить:

- какие файлы изменены;
- что именно изменено;
- почему это было изменено;
- как проверялось;
- результат проверки;
- возможные риски.

---

### 4. Не менять проект без явной необходимости

Особенно осторожно работать с:

- `.github/workflows/`;
- VPS cron;
- `vps_pipeline.py`;
- `vps_satellite_pipeline.py`;
- `vps_ai_pipeline.py`;
- GitHub Pages;
- Open-Meteo запросами;
- EUMETSAT API;
- существующими JSON-файлами;
- системой AI-очереди.

---

## Обмен информацией между AI

Для каждой значимой темы использовать отдельный файл:

`docs/topics/`

Примеры:

- `OPEN_METEO.md`
- `EUMETSAT.md`
- `FRONTS.md`
- `VPS.md`
- `AI_PIPELINE.md`
- `GITHUB_PAGES.md`

Каждый AI перед началом работы должен прочитать
файл соответствующей темы.

После существенного изменения необходимо обновить
соответствующий файл.

---

## Формат записи о проблеме

**Проблема**

Краткое описание.

**Фактические симптомы**

Логи, ошибки, наблюдаемое поведение.

**Причина**

Подтверждённая причина.

Не писать предположение как факт.

**Решение**

Что изменено.

**Проверка**

Какие команды или тесты были выполнены.

**Результат**

Что получилось после изменения.

**Статус**

- работает;
- требует наблюдения;
- не исправлено;
- требует решения пользователя.

---

## Текущий принцип работы

ChatGPT:

1. анализирует проблему;
2. проверяет архитектуру;
3. формулирует задачу;
4. проверяет результат.

Claude:

1. читает инструкции;
2. изучает связанные файлы;
3. реализует изменение;
4. тестирует;
5. фиксирует результат.

---

## Главное правило

Не считать задачу выполненной только потому,
что код изменён.

Задача выполнена только после проверки
фактического результата.
