# Генетический бот: поиск стратегий по истории (тема bot_genetic)

## Цель (пользователь, 2026-11-02)
Прийти к боту, который сам создаёт и выбирает стратегии, анализируя большой объём исторических данных (ориентир - класс «генетических» ботов в статье https://blog.whitebit.com/what-is-crypto-algo-trading-and-how-does-it-work/). Новый чат пользователь начинает фразой «читай docs/topics/bot_genetic.md».

## Договорённости по подходу (мнение Claude, пользователь согласился идти этим путём)
- Риск: чем мощнее поиск, тем сильнее переобучение; миллионы проверок найдут «идеал» даже на случайных данных. Уже видно в малом: WF-сканер 130 оценённых, 9 PASS (около шума), корреляция подбор->тест 0.07.
- Геном ограниченный: блоки фильтр режима, триггер, подтверждение, выход; мало параметров.
- Фитнес: только отрезки вперёд (walk-forward), после удвоенных издержек, учитывать худший отрезок, штраф за сложность, считать число проверенных вариантов; метрика БЕЗ верхних выбросов и медиана сделки (находка: MACD на ZEC 1h держится на единичных сделках до +45%).
- Отложенные данные и пары, которых поиск не видел; проверка самого поисковика на перемешанных/случайных данных (он не должен находить «стратегии»); прошедшие идут на бумажного бота вперёд.
- Первый прототип на 1h/4h (на ТФ до 30m комиссия съедает; по нашим тестам слабый плюс на 1h-4h).

## Прототип v1 (2026-11-02): сделан, запущен, результат отрицательный
- Код: bot/genetic/genetic.py + bot/genetic/index.html; на VPS /opt/trading-bot/genetic/ (results.json, run.log), служба genetic-panel на порту 18096 (туннель добавить: -L 18096:localhost:18096).
- Геном: ТФ (1h/4h), сторона (лонг/шорт/оба), триггер (EMA-пересечение, MACD, RSI, Дончиан, Боллинджер; флаг tm = против/пробой/импульс), режим (нет / SMA по тренду или против / ATR относительно своей средней), подтверждение (нет / объём / свеча / RSI14 к 50), выход (держать 6-48 свечей, SL и TP в ATR). Одна позиция за раз (интервал между входами не меньше срока удержания). Вход по открытию следующей свечи, при одновременном касании SL и TP считается SL.
- Фитнес: зона поиска = первые 70% времени, 4 последовательных блока; фитнес = худший блок (среднее без верхних 5% сделок минус стандартная ошибка) минус 0.01 за каждый компонент сложности минус штраф за отрицательную медиану; издержки 0.20% за круг (x2); нужно >=3 блока по >=20 сделок и >=80 сделок всего. Считаются проверенные варианты (по действующим генам).
- Проверка: отложенные последние 30% времени на парах поиска; невиданные пары XRP, DOGE, ZEC, TREE, KORUB, NIL целиком; PASS = отложенное и невиданные > 0 при n>=40 и >=половины невиданных пар в плюсе; отдельно счёт «+ по медиане». Тест на шуме: те же данные с перемешанными барами, 3 прогона.
- Проверка самого поисковика (локально, синтетика): на случайном блуждании ничего не находит; с заложенной автокорреляцией доходностей 0.35 находит пробойные стратегии (29 из топ-30 проходят отложенные и невиданные), на шуме 0. Слабая автокорреляция 0.12 после издержек x2 не находится (издержки больше края).
- Результат на реальных данных (популяция 200, 40 поколений, около 6300 проверенных вариантов): лучший фитнес -0.243 (шум: -0.344 / -0.317 / -0.183), прошедших 0 из 30 и у реальных, и у шума, лучший отложенный -0.207, лучший на невиданных -0.127. Лучшие геномы - MACD на 1h с сотнями сделок и средним около -0.4..-0.5% на сделку. Вывод: после удвоенных издержек края на 1h/4h в этом классе правил поисковик не нашёл, от шума реальные данные не отличаются. Согласуется с WF-сканером и тестом MACD.
- Свойства: эпоха ~1 с на поколение (2 процесса, nice 19), весь прогон с шумом около 2.5 минут.

## Технические детали
- Страницы результатов: статический index.html + results.json, раздаёт python http.server на 127.0.0.1 (systemd-служба), расчёт запускается nohup nice -n 19 от пользователя tbot через мост; перебор по 12 ТФ x 20 пар для MACD занял около 40 секунд.
- Python с pandas на VPS: /opt/trading-bot/venv/bin/python (системный /usr/bin/python3 без pandas). На VPS 2 ядра, 12 ГБ.
- Запуск genetic: su -s /bin/sh tbot -c "cd /opt/trading-bot/genetic && GEN_POP=200 GEN_GENS=40 GEN_NOISE=3 GEN_WORKERS=2 nohup nice -n 19 /opt/trading-bot/venv/bin/python genetic.py > run.log 2>&1 &". Переменные: GEN_CACHE, GEN_OUT, GEN_POP, GEN_GENS, GEN_NOISE, GEN_WORKERS, GEN_UNSEEN.
- Выкладка файлов: git fetch в /opt/weather-pipeline/repo, затем git show origin/main:bot/genetic/<файл> > /opt/trading-bot/genetic/<файл>, chown tbot.
- Мост работает от root; токен GitHub в личных настройках пользователя, срок жизни ограничен.
