# Система выходов с самообучением (exit_learning)

Запрос пользователя (2026-11-07): выход нельзя закрывать по жёсткому шаблону, каждая сделка индивидуальна; вход ещё можно привязать к шаблону, выход нет. Нужен бот «с ИИ, который понимает, что делает»: сопровождение каждой позиции, обучение НЕ только на журнале решений пользователя (decisions.jsonl, ручные переносы стопа/цели и их контекст), но и на анализе истории. Пользователь просит серьёзный алгоритм самообучения, не уровня детского сада.

## Принципы (чтобы не обмануть самих себя)
- Любая оценка только вне выборки: разбиение по времени (обучение раньше, проверка позже) и по парам (проверка на парах, которых не было в обучении). Подбор по одной выборке без проверки не считается результатом.
- Контроль: те же входы со случайными моментами; учитываем число перебранных вариантов (в прошлых бэктестах лучший из ~1000 вариантов всегда выглядит «значимым»: ожидаемый максимум шума diff/se около 3.3).
- Только данные до текущей свечи; комиссии: вход тейкер 0.05%, цель мейкер 0.02%, стоп/время тейкер 0.05%.
- Жёсткий предохранитель: начальный стоп (R = max(1.2 ATR, 0.5%)) модель не расширяет; она может только подтягивать стоп, закрывать часть/всё, держать. При низкой уверенности модели работает базовая политика.
- Допустим результат «край не найден»: тогда выходы остаются простыми и управляемыми пользователем, а мы это знаем по данным.
- Честное ограничение: при ненулевой комиссии выход сам по себе не создаёт положительного ожидания, если у входа его нет; выход меняет форму распределения (хвосты, доля прибыльных, просадка) и может использовать моментум/возврат к среднему, если они есть на выбранном ТФ.

## Этапы
0. Данные: 26 пар, 5m, 60 суток (scripts/exit_lab.py, кэш /tmp/fs/kl_*.npy на VPS); позже 15m/1h и более длинная история.
1. Лаборатория политик (exit_lab.py): шаблоны выхода (цель kR, выход по времени, безубыток+трейлинг, частичная цель) на ОДНИХ входах (случайные и по каналу); потолок ORACLE (лучший выход задним числом) только для масштаба.
2. Модель ценности продолжения: в каждой свече открытой позиции признаки состояния (R сейчас, пик R, откат от пика, возраст, ATR сейчас к ATR входа, положение в канале Fixed N в сигмах, моментум 3/12 свечей в ATR, всплеск объёма, положение закрытия в диапазоне свечи, расстояние до EMA, знак тренда старшего ТФ, сторона) -> ожидаемый результат «держать» против «выйти сейчас», метки из симуляции продолжения на истории (много входов: случайные + канал + реальные входы бота). Модели: линейная (база) и градиентный бустинг (отдельное окружение /opt/exit-lab/venv, venv бота не трогаем; на VPS сейчас только numpy и pandas).
3. Политика: действия {держать, закрыть, подтянуть стоп на уровень X, закрыть часть}; обучение/выбор на периоде A, проверка на периоде B и на других парах.
4. Журнал пользователя: поведенческое клонирование (сравнение «как действовал он» и «что сделала бы модель») когда наберётся достаточно ручных действий (на 2026-11-07 в decisions.jsonl всего 20 записей, ручное одно). Дописать в журнал причину входа и состояние на каждом ручном действии.
5. Онлайн в «тени»: модель рядом с реальным выходом на бумажных счетах пишет, что бы сделала, без влияния на сделки; сравнение на живой серии; затем включение на отдельном счёте.
6. Переобучение раз в неделю (walk-forward), откат на базовую политику при деградации.

## Результаты этапа 1 (2026-11-07, exit_lab.py, VPS, 26 пар, 5m, 60 суток)
- Входы: rand 13050 (случайные свечи и стороны), chan 12423 (касание границы скользящего канала Fixed N=60 по направлению, user = with + flat, закрытие внутри канала). Вход по рынку, R = max(1.2 ATR, 0.5%).
- Все 12 шаблонных политик (цель 1/1.5/2/3 R, выход по времени 6/12/24/48 свечей, безубыток+трейлинг 1/2/3 ATR, частичная цель) дают на случайных входах net -0.084..-0.100% на сделку, на входах по каналу -0.076..-0.085% (комиссия круга 0.07-0.10%, то есть до комиссий около нуля). Политики между собой различаются в пределах se (0.006-0.013), обе половины периода совпадают. Выбирать «лучший шаблон выхода» бессмысленно.
- Вход по каналу против случайного при тех же выходах: +0.006..+0.021% (diff/se 0.3..2.4, в основном <2): канал как триггер входа почти ничего не добавляет.
- ORACLE (лучший выход по закрытиям в 48 свечах задним числом): +1.2% на сделку при 85% прибыльных. Это потолок для масштаба (знание будущего), не достижимый результат; реально достижимая доля неизвестна и определится этапом 2.
- Вывод: преимущество выхода возможно только как функция СОСТОЯНИЯ позиции (моментум, откат от пика, объём, положение в канале, тренд ТФ и т.д.), а не как фиксированный шаблон. Это и проверяет этап 2.
- [ ] Этап 2: окружение /opt/exit-lab/venv (lightgbm, scikit-learn, pandas), набор состояний «позиция-свеча» из тех же входов, метка = выигрыш от продолжения против выхода сейчас, обучение на первых ~40 сутках и парах A, проверка на последних ~20 сутках и парах B.
