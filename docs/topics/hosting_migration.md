# Миграция хостинга: перенос compute-слоя с GitHub Actions на VPS

## Purpose & context

Текущий пайплайн (`gh_pipeline.py`, `gh_satellite_pipeline.py`, `gh_ai_pipeline.py`) работает целиком на GitHub Actions: Termux (job 1001, каждые 15 мин) шлёт только лёгкий `workflow_dispatch`-триггер, вся реальная работа — на эфемерных раннерах GitHub. Git используется как единственная база данных и IPC между тремя независимыми скриптами (каждый коммитит и пушит в main сам по себе).

22–23.08.2026 при диагностике зависшего Gemini-видео вскрылись структурные боли этой архитектуры:
- **Гонки при пуше** — независимые коммиты от разных пайплайнов иногда «склеиваются» GitHub в одно push-событие, путается атрибуция в UI Actions (see `docs/topics/main_pipeline.md` при необходимости деталей инцидента).
- **Логи Actions недоступны напрямую** — редиректятся на `blob.core.windows.net`, домен не в whitelist сети Claude; пришлось городить временный debug-шаг, пишущий stderr в файл репозитория через API.
- **Отсутствие персистентности** — раз у эфемерных раннеров нет своего диска между запусками, весь стейт вынужденно тащится через git commit — отсюда рост `.git` и общая хрупкость.
- **Дублирование зависимостей** — numpy был прописан в одном workflow (`make_video.yml`) и забыт в другом (`ai_pipeline.yml`), из-за чего Gemini-видео тихо не обновлялось с 20.08 до фикса 22.08.

**Решение:** перенести compute-слой (все cron-скрипты пайплайна) на постоянный VPS с root-доступом и своим диском. Судьба статики (index.html и т.д. на GitHub Pages) — под вопросом, см. «On the horizon».

## Current state

**Ход решения (хронология этой сессии):**
1. Рассматривался VPS у **CityHost** (тариф KVM-35: 35GB SSD / 2 vCPU / 2GB RAM) — **отклонён**. Цена «от 393.60 грн/мес» требует предоплаты за 36 месяцев; реальная помесячная цена — 656 грн/мес (зачёркнутая). Слишком дорого и рискованно платить на 3 года вперёд ради хобби-проекта.
2. Рассматривался **Oracle Cloud Free Tier** (Always Free: Ampere A1 ARM, до 4 OCPU / 24GB RAM) — бесплатно навсегда.
3. Была путаница с URL: `oracle.com/ua` — обычный корпоративный сайт Oracle (продукты для бизнеса), выглядит похоже, но это НЕ страница регистрации на облако. Правильный вход подтверждён: **`https://www.oracle.com/cloud/free/`** → кнопка «Start for free» / «Розпочати безкоштовно» → ведёт на `signup.cloud.oracle.com`.
4. Как запасной вариант обсуждён **Hetzner Cloud** (Германия) — тариф CX22 (2 vCPU/4GB RAM), помесячная/почасовая оплата без минимального контракта, ~€4–5/мес. Украина есть в списке стран биллинга на сайте Hetzner.
5. Руслан колебался по поводу Oracle («не лежит»), но в итоге **решил регистрироваться на Oracle Cloud Free Tier** — бесплатно навсегда перевешивает более муторную регистрацию.

**Статус: регистрация ещё не начата / в процессе.** Claude помогает пошагово, по скриншотам.

## On the horizon

Чек-лист регистрации и переноса (по порядку):

- [ ] Открыть `https://www.oracle.com/cloud/free/` → «Start for free» / «Розпочати безкоштовно»
- [ ] Заполнить форму регистрации, подтвердить email
- [ ] Привязать карту для верификации личности (реальная Visa/Mastercard дебетовая или кредитная; одноразовые/виртуальные карты обычно не проходят). Списания не ожидается, максимум временный холд.
- [ ] **Выбрать Home Region — решение необратимое.** Брать ближайший из доступных регионов с адекватным пингом до Одессы (конкретный список появится на форме — фиксировать выбор осознанно, переиграть нельзя).
- [ ] После регистрации дадут $300 триальных кредитов на 30 дней — **не трогать**, работать только в рамках Always Free, чтобы не словить случайный платёж после окончания триала.
- [ ] Создать Compute-инстанс: shape **«VM.Standard.A1.Flex» (Ampere ARM, Always Free eligible)**, образ — **Ubuntu ARM64** (не x86!).
- [ ] Если при создании инстанса ошибка «Out of host capacity» — известная особенность Oracle Free Tier, пробовать повторно позже или другой Availability Domain в том же регионе.
- [ ] Сохранить SSH-ключ (Oracle сгенерирует пару или даст загрузить свой публичный) — приватный ключ понадобится Claude для входа на сервер.
- [ ] **Руслану нужно будет добавить IP/домен VPS в network settings Claude** (allowed_domains) — иначе песочница Claude физически не сможет достучаться до сервера по SSH.
- [ ] После получения VPS — миграция скриптов: убрать `git add/commit/push` из `gh_pipeline.py`/`gh_satellite_pipeline.py`/`gh_ai_pipeline.py`, заменить на прямую запись файлов на диск.
- [ ] Настроить cron/systemd timers на сервере вместо цепочки `workflow_dispatch` (satellite → full → ai).
- [ ] Решить судьбу Termux job 1001 — скорее всего на пенсию, триггер берёт на себя cron сервера.
- [ ] Решить судьбу статики: (а) оставить на GitHub Pages, VPS просто периодически пушит обновлённые data/html туда; (б) полностью увести сайт на VPS с nginx, отказаться от GitHub Pages.

## Key learnings & principles

- **Home Region в Oracle Free Tier выбирается один раз навсегда** — нет пути назад, решение принимать осознанно на первом же прохождении формы.
- **Oracle иногда флагает регистрации** как подозрительные — если откажет с первого раза, штатный путь: тикет в поддержку или повтор с другой картой/браузером. Не тупик, известная особенность.
- **Ценовой трюк CityHost и подобных хостеров:** headline-цена «от X грн/мес» обычно требует предоплаты на максимальный срок (36 мес); реальная помесячная цена — то, что зачёркнуто рядом. При сравнении хостингов всегда смотреть на реальный month-to-month тариф, а не на «от».
- **Hetzner Cloud:** без минимального контракта, счёт выставляется по факту (почасовая ставка, но не выше месячного потолка), Украина явно в списке стран для биллинга — надёжный fallback, если Oracle не взлетит.
- **Корень сегодняшних архитектурных проблем (гонки пушей, недоступные логи, git-как-БД)** — структурная особенность GitHub Actions (эфемерные раннеры без диска), не лечится в рамках текущей архитектуры. Отсюда и решение переезжать, а не патчить симптомы.

## Approach & patterns

- Регистрация и первичная настройка VPS — интерактивно, по скриншотам от Руслана; Claude подтверждает следующий шаг и заранее предупреждает о необратимых решениях (регион, shape инстанса, образ ОС) до того, как они будут приняты.
- После получения VPS — Claude сможет выполнять реальные команды на сервере (SSH), но только после того как Руслан добавит IP/домен сервера в network settings Claude (тот же паттерн, что и с GitHub PAT, только теперь для живого сервера).
- Как и с репозиторием — Claude работает с сервером напрямую сам, без участия Руслана в Termux/консоли, кроме шагов, требующих его физического подтверждения (оплата, выбор в веб-форме до выдачи Claude доступа).
