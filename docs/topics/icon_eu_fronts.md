## Технические детали
- Скрипт: scripts/icon_front_very_far_snapshot.py. Новое поле t850 (ICON-EU pressure-level T 850), скачивается вместе с остальными.
- Фронты считаются один раз на всю область, потом рисуются по тирам: слой {ts}_fronts.png, ключ files.fronts в manifest.json (у старых снимков ключа нет — страница это учитывает).
- Метод: θe (Bolton) на 850 → сглаживание → TFP = -∇|∇θ|·∇θ/|∇θ| → нулевая изолиния там, где |∇θ|>порог и градиент проходит максимум поперёк (dTFP/dn>0). Тип по адвекции: V850·n>+1.5 м/с холодный, < -1.5 тёплый, иначе стационарный (n смотрит в сторону тёплого).
- L/H: экстремум сглаженного PMSL в окне 500 км, отличие от среднего окна ≥1.5 гПа, не над рельефом >800 м.
- Порог-параметры переопределяются env: ICON_FRONT_GRAD_MIN, ICON_FRONT_MIN_KM.

## Как тестировать офлайн (без ожидания cron)

Раньше единственный способ проверить эффект от изменения порога — ждать следующего часового
прогона на VPS, а между прогонами меняется реальная погода, и непонятно, что на картинке
изменилось из-за параметра, а что из-за новой ситуации. Теперь можно заморозить один снимок
реальных полей и гонять по нему рендер сколько угодно раз офлайн.

**1. Один раз — снять снимок с реального прогона** (на VPS, там же, где обычно крутится cron):
```
ICON_FRONT_SAVE_TESTCASE=data/icon_front_testcase/case1.npz \
    python3 scripts/icon_front_very_far_snapshot.py
```
Прогон отработает полностью как обычно (скачает GRIB, обновит сайт), и рядом появится
`case1.npz` — сырые поля (PMSL, HSURF, T850, RELHUM850, U850, V850, FR_LAND и т.д.) без каких-либо
уже применённых порогов. Можно накопить несколько снимков под разные ситуации — спокойная
погода отдельно, выраженный циклон с фронтом отдельно — и подбирать пороги на каждой.

**2. Дальше — сколько угодно раз, без сети:**
```
ICON_FRONT_GRAD_PERCENTILE=90 python3 scripts/icon_front_replay.py \
    data/icon_front_testcase/case1.npz /tmp/front_test_out
```
Картинки лягут в `/tmp/front_test_out/<tier>_isobars.png` и `<tier>_fronts.png` для всех
трёх тиров (near/far/very_far). Меняешь переменную окружения — перезапускаешь — та же
погода, только новый порог. Разница между двумя прогонами по одному и тому же снимку —
это и есть чистый эффект параметра.

`case1.npz` в git не коммитится (`.gitignore`, `data/icon_front_testcase/`) — это локальный
рабочий файл на VPS, десятки МБ, смысла хранить в репозитории нет.

Файлы: `scripts/icon_front_very_far_snapshot.py` (функции `save_testcase`/`load_testcase`),
`scripts/icon_front_replay.py` (сам replay).

Прислали три предложения (фильтр по завихренности, притяжение конца фронта к L, новые дефолты).
Применил не дословно — патч был написан по более старой версии файла и at literally-replace
снёс бы уже сделанное подавление берег/горы. Смёржил руками:

1. **Фильтр циклонической завихренности** (`FRONT_REQUIRE_CYCLONIC_VORTICITY`, ENV
   `ICON_FRONT_REQUIRE_VORTICITY`, по умолчанию включён) — линия фронта должна лежать в зоне
   ζ>0 (циклонический изгиб ветра 850), иначе выбрасывается. Идея: сильный градиент θe поперёк
   гладкого антициклона — не фронт, а просто фон; у настоящего фронта всегда есть циклонический
   сдвиг ветра. Добавлено ПОВЕРХ (не вместо) существующего подавления берег/горы.
2. **Притяжение конца линии к центру L** (`FRONT_ATTRACT_TO_LOW_KM`, по умолчанию 300 км) —
   если конец сегмента обрывается ближе этого расстояния к центру L, достраивается прямой
   отрезок до самого центра. В присланном патче был баг: достраивали `xy`, но не `kind`/`nx`/`ny`
   той же длины — а они используются 1-в-1 по индексу для покраски (`LineCollection`) и
   расстановки значков-треугольников/полукругов. Без фикса это либо упало бы с несовпадением
   размеров, либо покрасило/расставило значки на смещённые индексы. Исправлено — паддинг
   значением с того же конца, откуда растягиваем.
3. **Новые дефолты**: `FRONT_GRAD_PERCENTILE` 93→88, `FRONT_MIN_KM` 350→300,
