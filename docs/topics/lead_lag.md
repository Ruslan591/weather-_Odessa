# «Паровозик»: связь альтов с BTC на 1m (lead_lag)

Вопрос пользователя (2026-11-17): цены монет движутся «паровозиком», какие-то раньше других; постоянна ли очередность и можно ли использовать как индикатор. Связано с шумом фильтра BTC 1m в Telegram-боте (docs/topics/telegram_bot.md): пользователь в последнем обновлении заменил проверку свечи BTC 1m в живом входе на свечу самой пары (docs/topics/live_web.md, версия 7); эффективность замены ещё не проверена (новых сделок нет). Пользователь перешёл на полуавтоматический режим Монитор.

## Что сделано (2026-11-17)
- bot/positions/tg_lead.py: shadow-метрика, только показ и запись, ничего не блокирует. По последним n=90 закрытым 1m свечам пары и BTC (общие по времени, публичные свечи data-api.binance.vision, кэш 25 с): rho (корреляция 1m-доходностей), beta = cov/var(BTC), zB = ход BTC за k=3 свечи / (сигма BTC * sqrt(k)), zG = отставание пары от ожидаемого по бете хода в сторону BTC, в сигмах остатка (zG > 0: пара отстаёт), лаг L=0..3 с максимальной корреляцией.
- Строка 📡 в посте слежения (мнение бота): «BTC 3м ход (z), пара ход, отст. z · ρ β лаг · вердикт». Вердикт: lag (rho >= 0.6, |zB| >= 1.5, zG >= 1.0: «отстаёт, ждём вверх/вниз»), ok (rho >= 0.6: «BTC-ориентир ок»), mid (rho 0.4-0.6: «связь средняя»), own (rho < 0.4: «своя жизнь, BTC не ориентир»).
- В feat мнения пишется ll = [rho, beta, zB, zG, лаг, ход BTC %, ход пары %] (и для отбоя, и для пробоя) -> журнал, разборы.
- Конфиг POS_DIR/tg_lead.json: {"mode": "shadow|off", "n": 90, "k": 3, "rho_min": 0.6, "zb_min": 1.5, "zg_min": 1.0}. Выключить: {"mode": "off"} или удалить файл tg_lead.py (tg_express подключает через try/except).
- Вписывание подписи поста в лимит Telegram 1024: bot/positions/tg_fit.py, функция fit(text, limit=1020), в tg_bot.fitcap; применяется в send_watch и в edit_watch (место под статус). Раньше подпись резалась на 1020 символах и терялся конец (цель, блок пробоя): так обрезалось 223 из 1302 постов. Ступени сжатия: короткие формы стандартных фраз, заголовок мнения без причины, все ✓ блока в одну строку, длинные ✗ по границе слова, убирается ℹ️ строгий BTC 1м, короче строка цели, убирается матрица отбой/пробой BTC и «сделка по режиму», крайний случай - строки с конца целиком. Худший случай (отбой + пробой + автоордер, 1644 символа) -> 961. Удалить файл -> старая обрезка по длине.
- Выкладка: scripts/deploy_tg_lead.sh (name=md5|NEW, бэкап в /opt/tg-notify/bak, проверка импорта и живого расчёта, автооткат). Выложено 2026-11-17 ~06:14 и 06:54 UTC (tg_lead, tg_fit, tg_express, tg_bot), tg-bot-regr active. Живой пост в Telegram ещё не наблюдали (бот был в Сне), проверено на записях tg_watch.json без отправки.

## Технические детали: исследование scripts/leadlag_study.py (35 ликвидных пар из pairs.json, 10 суток 1m, запуск на VPS, результат /tmp/ll_out.txt)
- Связь почти вся на лаге 0. rho к BTC: ETH 0.90, BNB 0.88, SOL 0.85, DOGE 0.83, LINK 0.82, SUI 0.81, XRP 0.79, ADA 0.76, TAO 0.74, DOT 0.60, ICP 0.60, ATOM 0.52, PEPE 0.49, NIL 0.47, REZ 0.43, IOST 0.35, TREE 0.32, ASTER 0.30, PHA 0.28, TRX 0.24, HAEDAL 0.24, HUMA 0.20, RARE 0.12. Корреляция на лагах 1-5 у крупных около нуля (+-0.03; средний лаг 3 слегка отрицательный, -0.026). Небольшое следование за BTC на лаге 1 (0.08-0.13) у малых монет: ANIME, REZ, TREE, IOST, PHA, NIL, ATOM. Лучший лаг > 0 ни у одной пары.
- Событийный тест (|zB| >= 1.5, ход пары в сторону BTC за 3/5/10 мин, bps): при rho >= 0.6 следование около нуля или чуть отрицательное (-1.7/-0.9/-0.5; сам BTC -0.9/-0.3/+0.2, т.е. после 3-минутного импульса он слегка откатывается). zG < 0 (пара перестаралась): -2.6/-2.5/-1.9 (откат). Корзина 1 <= zG < 2: -0.9/+2.8/+4.6, но zG >= 2 не лучше (+1.3/-0.5/-4.2, n=446): зависимость немонотонная. Сигнал (rho >= 0.6 и zG >= 1.0): train 60% времени -1.8/-2.5/-0.5 bps, test 40% +0.2/+4.7/+4.9: знак нестабилен. Комиссия туда-обратно 8-20 bps превышает любой из этих эффектов.
- rho < 0.6: общий дрейф в сторону BTC +0.7/+0.8/+1.5 bps, корзина zG >= 2: +4.5/+9.0/+10.4 (n=248): единственное место, где отставание похоже на догоняющий ход; нужен период дольше и проверка на отложенном куске, до того не использовать.
- По парам сигнал на 5 мин: DOT +24.9 (n=30, hit 0.73), PEPE +26.6 (n=17), крупные +1-4 bps; малые n, множественные сравнения.
- Оговорки: события разных пар на одной минуте делят одно движение BTC, независимая выборка намного меньше заявленных n=32095, t-статистики завышены; период 10 дней, один режим (падающий рынок, BTC -4.6% за 24 ч).
- Вывод: главный показатель - rho, не zG. Для пар с rho >= 0.6 BTC 1m годится как ориентир, при rho < 0.4 это шум (RARE, HUMA, HAEDAL, TRX, PHA, ASTER, TREE, IOST), что поддерживает проверку по свече самой пары для слабосвязанных. Блокировать по zG не рекомендуется.
