# Живая страница бота (Mini App + веб, WebSocket)

Решение пользователя 2026-11-13: видеть всю работу бота онлайн, не через посты. Только чтение, торговых команд нет.

## Как устроено
- Сервис live-web (systemd, user tbot, Nice 10, CPUQuota 25%, MemoryMax 200M), код bot/live/live_web.py, страница bot/live/index.html, установка scripts/install_live.sh, на VPS /opt/trading-bot/live/.
- Адрес: https://130-61-25-212.nip.io/live/ (Caddy: /live* -> 127.0.0.1:18110, остальное по-старому на 8080, бэкап Caddyfile.bak_*). Порт 18110 слушает только localhost.
- Вход: Telegram Mini App (кнопка меню «Онлайн» у бота, проверка подписи initData по TG_TOKEN и TG_USER_ID) или резервная секретная ссылка с токеном из /opt/trading-bot/live/token.txt (ссылка отправлена в личный чат бота; токен нельзя печатать в вывод моста, он попадает в репозиторий). До 3 подключений, проверка Origin, после 8 неудачных попыток за 10 минут бан по IP.
- Данные: цены Binance через публичный поток data-stream.binance.vision (aggTrade по парам позиций, ордеров, слежений плюс kline 1m BTC), сервер ретранслирует каждые 0.2 с; состояние раз в секунду по изменению (acct-api GET /api/claude, orders.json, tg_watch.json, tg_btc1m_last.json, tg_regime.json, tg_slots.json, tg_mode.json, tg_live1m.json); события из хвоста decisions.jsonl и из изменений ордеров tg_* (отказы и вход по live1m).
- Страница: счёт (эквити и нереализованное пересчитываются по живым ценам), открытые позиции (P&L, R, полоса стоп-вход-цель), ордера в ожидании (статус проверки BTC 1m, расстояние от линии), слежения (расстояние до линии в ATR), лента событий, шапка: BTC, живая свеча 1m, цвета закрытых свечей, режим рынка.

## Технические детали
- Решения бота идут циклами (~30 с), страница показывает их сразу, но чаще не станут: ускорение цикла отдельная задача.
- orders.json больше 5 МБ, сервис держит только последние 400 ордеров; память сервиса ~60-100 МБ.
- Проверено: тест на синтетике (вход, отказ, Origin, подпись Telegram), WebSocket через публичный HTTPS и Caddy. Живое открытие в Telegram и на телефоне ещё не проверялось.
- Известные упрощения: P&L позиции без комиссий; после частичного закрытия (tp1) P&L считается от полной ставки; текст событий из decisions.jsonl общий, форматирование будем улучшать по примерам.

- Запрос пользователя: на порту управления 18111 (туннель, ctl=true) у открытой позиции есть управление; нужно такое же для ордера в ожидании: перестановка, отмена, стоп и цель.

- Цепочка: страница -> WS act (ord_cancel, ord_edit с price/stop/tp) -> live_web.handle_act -> acct-api POST /api/claude -> pos.api_action -> chan_orders.manual_order. Всё под pos.lock(), как cycle(). Каждое действие в ctl_audit.log.
- Проверки сервера (manual_order): ордер pending; рыночный (tg_market) только отменяется; вход лимитом: long ниже цены, short выше (иначе исполнится сразу), стоп-ордер tg_stop наоборот; стоп с «своей» стороны входа и до ликвидации (pos.LIQ); цель с «своей» стороны и не ближе 0.15% от входа; при переносе входа осталось время жизни ордера.
- Правка помечает ордер: man (автоматика не пересчитывает и не отменяет: ретест, «пересчёт границы», «условия исчезли», «правило заменено»; дубль рядом не ставится), edit_t, edits (история), approved_t (если не было: режим Сон ордер не отменит), px_t и placed_t = начало следующей минуты (без заглядывания в прошлое; старая заливка с более ранней свечи отбрасывается), man_tp при смене цели. Теперь, если цель на ордере правили вручную (man_tp), при исполнении она записывается в позицию как tp_manual. Для ордеров без ручной цели поведение прежнее (линия «цель» на графике ордера может не совпадать с реальной целью позиции).

Сообщения в Telegram о включении и снятии галочки отключены (у алерта без ответа только тихо убираются кнопки). Посты слежения с галочкой, график после каждой свечи и сообщения о действиях по позициям и ордерам остаются.
- График слежения (порт 18111): кнопки «Отбой SHORT/LONG» и «Пробой LONG/SHORT» (сторона и линия берутся из слежения) -> выбор входа (рынок, лимит, стоп-ордер; для пробоя стоп за линией, лимит на ретесте) -> выбор цели (отбой: противоположная линия, середина, 1/4, 3/4 канала; пробой: 0.5, 1, 1.5 высоты канала за линией). Страница шлёт act watch_order -> acct-api -> pos.api_action -> chan_orders.manual_watch_order -> tg_gate.inbox_any (событие w_place в tg_inbox.jsonl, как нажатие кнопки в Telegram). Ордер, проверки и итог (пост ордера, при отказе сообщение с причиной) делает ближайший цикл, как для кнопки; на странице сразу «Запрос принят», отказа по существу (цель уже пройдена и т.п.) страница не видит, он приходит в Telegram. Работает только в режиме Монитор. В журнал w_place пишется с via=page.
- Живая проверка рыночного входа (chan_orders._live1m_gate): теперь смотрит текущую свеча 1m САМОЙ ПАРЫ (short: цена ниже открытия свечи, long: выше; ровная свеча = ждём), а не BTC. Причина: вход делается по этой паре, её свеча прямо показывает реакцию у линии, а BTC-подтверждение уже есть в решении на входе (RSI BTC 1m, tg_btc1m). Обратно на BTC: tg_live1m.json {"source": "btc"} (применяется сразу). В записи ордера live1m появилось поле src (pair/btc), в событии live1m поля sym и src; тексты в Telegram и на странице называют свечу той пары. Ордера, созданные до обновления, считаются как BTC.
- Шкала в карточке открытой позиции: если стоп уже в зоне безубытка или за входом в сторону прибыли (допуск 0.02% от входа), шкала зелёная (от тёмно-зелёного к зелёному); иначе прежняя красно-зелёная.
