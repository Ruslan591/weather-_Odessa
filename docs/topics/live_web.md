# Живая страница бота (Mini App + веб, WebSocket)

Решение пользователя 2026-11-13: видеть всю работу бота онлайн, не через посты. Только чтение, торговых команд нет.

## Как устроено
- Сервис live-web (systemd, user tbot, Nice 10, CPUQuota 25%, MemoryMax 200M), код bot/live/live_web.py, страница bot/live/index.html, установка scripts/install_live.sh, на VPS /opt/trading-bot/live/.
- Адрес: https://130-61-25-212.nip.io/live/ (Caddy: /live* -> 127.0.0.1:18110, остальное по-старому на 8080, бэкап Caddyfile.bak_*). Порт 18110 слушает только localhost.
- Вход: Telegram Mini App (кнопка меню «Онлайн» у бота, проверка подписи initData по TG_TOKEN и TG_USER_ID) или резервная секретная ссылка с токеном из /opt/trading-bot/live/token.txt (ссылка отправлена в личный чат бота; токен нельзя печатать в вывод моста, он попадает в репозиторий). До 3 подключений, проверка Origin, после 8 неудачных попыток за 10 минут бан по IP.
- Данные: цены Binance через публичный поток data-stream.binance.vision (aggTrade по парам позиций, ордеров, слежений плюс kline 1m BTC), сервер ретранслирует каждые 0.2 с; состояние раз в секунду по изменению (acct-api GET /api/claude, orders.json, tg_watch.json, tg_btc1m_last.json, tg_regime.json, tg_slots.json, tg_mode.json, tg_live1m.json); события из хвоста decisions.jsonl и из изменений ордеров tg_* (отказы и вход по live1m).
- Страница: счёт (эквити и нереализованное пересчитываются по живым ценам), открытые позиции (P&L, R, полоса стоп-вход-цель), ордера в ожидании (статус проверки BTC 1m, расстояние от линии), слежения (расстояние до линии в ATR), лента событий, шапка: BTC, живая свеча 1m, цвета закрытых свечей, режим рынка.

## Технические детали
- Решения бота идут циклами (~30 с), страница показывает их сразу, но чаще не станут: ускорение цикла отдельная задача.
- orders.json больше 5 МБ, сервис держит только последние 400 ордеров; память сервиса ~60-100 МБ.
- Проверено: тест на синтетике (вход, отказ, Origin, подпись Telegram), WebSocket через публичный HTTPS и Caddy. Живое открытие в Telegram и на телефоне ещё не проверялось.
- Известные упрощения: P&L позиции без комиссий; после частичного закрытия (tp1) P&L считается от полной ставки; текст событий из decisions.jsonl общий, форматирование будем улучшать по примерам.
