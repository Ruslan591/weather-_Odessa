# Заметки пользователя по тенями и входам: описание -> правило (shadow_notes)

Формат: пользователь присылает описание сделки словами (в чат или ответом в канале «Фон»), Claude записывает сюда, меняет правила бота и отмечает, что сделано. Заметки из канала сохраняются ботом в shadow_notes.jsonl (POS_DIR) с привязкой к тени; сюда переносятся при разборе.

## №1 (2026-11-20) INJUSDT 19.11 15:16, сделку открыл бот до появления правила
Описание: ровно в 15:16:00 открывать было нельзя; нужно было подождать начала отрисовки свечи 1m 15:16, она с самого начала пошла против сделки.
Причина: в первые секунды новой минутной свечи один тик даёт «по ходу».
Правило (сделано): не подтверждать вход, пока свеча контроля моложе age_frac (1/6) своей длины; если движения нет, ждать движения, а не отсекать вход (уточнение пользователя). patch_gate_age.py.

## №2 (2026-11-20) старшие таймфреймы и доля времени
Описание: на старших таймфреймах одной 1m может быть мало (шум): для 15m брать 5m. Та же пропорция по времени: для 1m ждём 10 с (1/6), для 5m 1/6 от 5 минут (50 с). Значение 1/6 не окончательное, возможно изменим.
Правило (сделано): свеча контроля на ступень ниже таймфрейма (5m->1m, 15m->5m, 1h->15m, 4h->1h, 1d->4h), age_frac = 1/6 (tg_live1m.json), потолок ожидания растёт с долей. patch_gate_tf.py.

## №3 (2026-11-20) регрессия 1m для коррекции входа
Описание: пользователь использовал пробой канала регрессии 1m, наложенного на график 5m; не утверждает, что это правильно, нужно изучать; «это помогает».
Правило (сделано как эксперимент): вариант B теней ждёт пробоя канала регрессии свечи контроля (окно 40..350 по максимуму |r|, полосы ±2 sd) по ходу сделки; у всех теней пишется снимок регрессии (reg: окно, r, наклон, z, пробой). Сравнение A и B после накопления сделок.

## №4 (2026-11-20) время входа
Описание: в времени входа добавить секунды для контроля.
Правило (сделано): секунды в сообщениях теней, журнале реальных позиций (открыта / закрыта), на странице.

## №5 (2026-11-20) входы выше 5m

Сделано: сканер выключен, тени только на 5m (shadow_cfg tfs), открытые #44, #45, #47, #48 удалены вместе с сообщениями канала. Суть ошибки пользователь пока не назвал: выяснить.

## №6 (2026-11-20, разбор 21.11) LTC 1h #42: вход на красной свече, одной 15m мало
Описание пользователя: «Неправильный вход. Параллельно нужно проверять и более младшие таймфреймы. Точка входа выбрана неправильно: предыдущая свеча 1ч 20:00 была медвежья». Отбой по LTC был либо на 2 часа раньше, либо на 2 часа позже. #42, #43B, #46B: все LONG LTC 1h за 1.5 часа.
Что показал разбор (1s свечи Binance на момент входа 19:06:10 UTC): 15m свеча 6 с из нужных 150 с по ходу long, 1m 6 с из 10 с; 15m была выше открытия на 0.01 (0.025%) и этого хватило, потому что правило смотрело только текущее направление 15m и возраст свечи (370 с), а не сколько времени цена держалась по ходу. 5m держалась 60 с (норма 50).
Правило (сделано, patch_gate_multi.py, deploy_shadow7.sh, действует и на реальные ордера из слежения):
- Параллельно все младшие таймфреймы: 5m -> 1m; 15m -> 5m, 1m; 1h -> 15m, 5m, 1m; 4h -> 1h, 15m, 5m, 1m; 1d -> 4h, 1h, 15m, 5m, 1m. Вход только если по ходу все.
- 1/6 считается как ВРЕМЯ, которое цена непрерывно держится по ходу сделки относительно открытия свечи (по закрытиям 1s свечей), а не как возраст свечи и не как часть тела: 1m 10 с, 5m 50 с, 15m 150 с, 1h 10 мин. Не было движения по ходу: ждём, не отсекаем.
- Настройки tg_live1m.json: chain (false = одна свеча на ступень ниже), dir_time (false = возраст вместо времени по ходу), age_frac.
Не сделано: проверка направления свечи самого сигнального таймфрейма (1h красная при long) отдельным условием; спросить пользователя.

## №7 (2026-11-21) нумерация теней
Описание: #42, #43B, #46B за 1.5 часа. B даём тот же номер, что у A, с буквой B; не раздувать нумерацию.
Правило (сделано, tg_shadow.py): на один сигнал один показываемый номер (поле n), A: #42, B: #42B. Внутренний id записи остаётся уникальным (по нему связаны сообщения канала, пути, позиции). Для старых записей без n показывается id. В заметках «#42» привязывает к обеим, «#42B» только к варианту B. Страница «Теневые» пока показывает внутренний id.
