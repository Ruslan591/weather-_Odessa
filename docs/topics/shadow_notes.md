# Заметки пользователя по тенями и входам: описание -> правило (shadow_notes)

Формат: пользователь присылает описание сделки словами (в чат или ответом в канале «Фон»), Claude записывает сюда, меняет правила бота и отмечает, что сделано. Заметки из канала сохраняются ботом в shadow_notes.jsonl (POS_DIR) с привязкой к тени; сюда переносятся при разборе.

## №1 (2026-11-20) INJUSDT 19.11 15:16, сделку открыл бот до появления правила
Описание: ровно в 15:16:00 открывать было нельзя; нужно было подождать начала отрисовки свечи 1m 15:16, она с самого начала пошла против сделки.
Причина: в первые секунды новой минутной свечи один тик даёт «по ходу».
Правило (сделано): не подтверждать вход, пока свеча контроля моложе age_frac (1/6) своей длины; если движения нет, ждать движения, а не отсекать вход (уточнение пользователя). patch_gate_age.py.

## №2 (2026-11-20) старшие таймфреймы и доля времени
Описание: на старших таймфреймах одной 1m может быть мало (шум): для 15m брать 5m. Та же пропорция по времени: для 1m ждём 10 с (1/6), для 5m 1/6 от 5 минут (50 с). Значение 1/6 не окончательное, возможно изменим.
Правило (сделано): свеча контроля на ступень ниже таймфрейма (5m->1m, 15m->5m, 1h->15m, 4h->1h, 1d->4h), age_frac = 1/6 (tg_live1m.json), потолок ожидания растёт с долей. patch_gate_tf.py.

## №3 (2026-11-20) регрессия 1m для коррекции входа
Описание: пользователь использовал пробой канала регрессии 1m, наложенного на график 5m; не утверждает, что это правильно, нужно изучать; «это помогает».
Правило (сделано как эксперимент): вариант B теней ждёт пробоя канала регрессии свечи контроля (окно 40..350 по максимуму |r|, полосы ±2 sd) по ходу сделки; у всех теней пишется снимок регрессии (reg: окно, r, наклон, z, пробой). Сравнение A и B после накопления сделок.

## №4 (2026-11-20) время входа
Описание: в времени входа добавить секунды для контроля.
Правило (сделано): секунды в сообщениях теней, журнале реальных позиций (открыта / закрыта), на странице.
