# Тени: пропущенные сигналы «ЗАХОДИТЬ» ведутся на бумаге (shadow_positions)

Состояние на 2026-11-21. Запрос пользователя: часть сигналов он пропускает по бытовым причинам; бот в его отсутствие должен делать то же, что он (ручной вход по рынку), на бумаге, с итогом и графиком, без влияния на счёт; пользователь разбирает ход сделок и по его описаниям правятся правила (docs/topics/shadow_notes.md).
Связано: telegram_bot.md (посты, вердикт, Автоордер), live_web.md (страница 18111), vps_bridge.md (выкладка).

## Что делает тень (боевым кодом счёта, ничего не переписано)
1. Сигнал: пост экспресса с мнением «заходить» без ордера Автоордера (tg_bot.send_watch -> tg_shadow.record). Что поставил бы Автоордер (ao_pick: сетап, цель), то ведёт тень.
2. Ордер строит chan_orders._tg_mkorder (те же формулы, что у ордера из слежения). Вход по рынку.
3. Фильтр входа chan_orders._live1m_gate один в один: свеча контроля пары идёт по ходу сделки, цена не ушла от линии дальше max_dist_atr, цель не слишком близко. Настройки из tg_live1m.json общие с реальными ордерами.
4. Позиция как при исполнении реального ордера (стоп по exit_cfg, комиссии, flat_brk), сопровождение боевым pos.step по 1m свечам (БУ, частичная цель, трейлинг, S/R, время, ликвидация). События сопровождения перехватываются подменой decisions.auto и идут в запись тени, в журнал решений счёта не пишутся.
5. Отфильтрованный сигнал ведётся вхолостую по плану (cf): видно, чего стоил фильтр.
6. Варианты: A (как вручную) и B (то же, но вход ждёт пробоя канала регрессии свечи контроля по ходу сделки, K=2.0 sd; пользователь так делал на графике 5m, не утверждает, что это правильно: изучается). Основные итоги по A, B отдельной строкой, в канал B не выкладывается (shadow_cfg b_post).
7. Снимок регрессии свечи контроля (окно, r, наклон, z, пробой) пишется на входе у всех теней (поле reg) для разбора.
8. Тень не трогает счёт: не пишет orders.json, positions.json, decisions.jsonl, не занимает слоты. Число одновременных теней не ограничено. Одна открытая тень на пару, сторону, таймфрейм и вариант. Если по слежению пользователь поставил реальный ордер (src_watch), тень снимается (taken).

## Правило свечи контроля (patch_gate_age.py + patch_gate_tf.py + patch_gate_multi.py в chan_orders, действует и на реальные ордера)
- Параллельно проверяются ВСЕ младшие таймфреймы сигнала (с 21.11, заметка №6): 5m -> 1m; 15m -> 5m, 1m; 1h -> 15m, 5m, 1m; 4h -> 1h, 15m, 5m, 1m; 1d -> 4h, 1h, 15m, 5m, 1m. Вход подтверждается, только если все свечи идут по ходу сделки.
- Доля age_frac (по умолчанию 1/6) это ВРЕМЯ, которое цена непрерывно держится по ходу сделки относительно открытия свечи (по закрытиям 1s свечей пары, для свечей от 1h по 1m): 1m 10 с, 5m 50 с, 15m 150 с, 1h 10 мин, 4h 40 мин. Не часть тела и не просто возраст свечи. Нет движения по ходу: ждём движения, вялую монету не отсекаем (заметки №1, №2, №6). Нет данных 1s: запасной вариант, возраст и текущее направление.
- Потолок ожидания: не меньше 10 минут и не меньше двух долей старшей свечи контроля плюс 5 минут (_gate_cap_ms).
- Настройка tg_live1m.json: {"age_frac": 0.1667, "chain": true, "dir_time": true}; chain false одна свеча на ступень ниже, dir_time false возраст вместо времени по ходу, age_frac 0 только направление. Применяется сразу. Тесты scripts/test_gate_multi.py (в deploy_shadow7.sh).
- Откат: бэкапы /opt/trading-bot/bak_shadow3_*, bak_shadow4_*, bak_shadow7_* (chan_orders.py, tg_shadow.py, shadow.json).
- Проверка задним числом (LTC #42, вход 19:06:10 UTC): 15m по ходу 6 с из 150, 1m 6 с из 10, 5m 60 с из 50: новое правило вход не пропустило бы.

## Перенос стопа swing_stop (с 21.11, deploy_shadow8 и deploy_shadow10)
После разворотной свечи 1m стоп переносится за Hi (short) / Lo (long) самой свечи пика хода (near=1), только ужесточение, зазор до цены не меньше 0.2 R, ход к пику не меньше 0.3 R. Только для теней (флаг sw), копия без правила в it.pb для сравнения. Параметры swing_cfg.json. История: заметка №8.

## Нумерация (с 21.11, deploy_shadow9)
Показываемый номер sn: A #65, B #65B, один сигнал с разными фильтрами. Внутренний id уникален (msg, shadow_paths, позиция). Канал, подтверждение заметки и панель «Онлайн» показывают одно и то же. Поле n у старых записей это номер источника, не использовать.

## СЕЙЧАС: входы выше 5m ОСТАНОВЛЕНЫ (решение пользователя 2026-11-20)
- Пользователь: все входы выше 5m неправильные, «там грубейшая ошибка» (суть не названа). Сканер tg-shadow-scan выключен (systemctl disable --now), shadow_cfg.json {"scan": false, "tfs": ["5m"]}: тени создаются только на 5m (record отклоняет остальные таймфреймы, очередь не разбирается).
- Открытые тени выше 5m (#44 AVAX 4h, #47 APT 1h) и их двойники B (#45, #48) удалены вместе с сообщениями в канале (scripts/shadow_drop_tf.py, бэкап shadow.json.bak_*). Закрытые остались (#42 LTC 1h -1.05 R). Отфильтрованные выше 5m остались в записях, холостой прогон по ним остановлен.
- 21.11 пользователь назвал суть: на старших таймфреймах вход проверялся одной свечью на ступень ниже, без 5m и 1m, и по возрасту, а не по времени по ходу (заметка №6, исправлено в deploy_shadow7). Сканер всё ещё выключен до решения пользователя. Раньше подозрения (не подтверждены): Подозрения (не подтверждены): вердикт и пороги подобраны на 5m; цель f и стоп для старших таймфреймов; правило свечи контроля на старших (на реальных ордерах оно тоже действует, если Монитор переключить на 15m/1h/4h/1d).
- Чтобы включить: shadow_cfg.json "tfs" и "scan": true, systemctl enable --now tg-shadow-scan.
