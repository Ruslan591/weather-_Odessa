## Почему не каждый прогон ICON EU даёт видео (диагноз 04.10, VPS-логи)

Gemini запускается только по триггеру ICON EU (`data/ai_schedule.json`: `model_triggers`) и по одной точке 12:05 UTC во вторник. Дальше три причины пропуска:

1. **Потеря свежего анализа откатом (главная).** 04.10 в 11:59 UTC ICON EU сработал, Gemini вернул 5892 символа, но `forecast_analysis_gemini.json` был перезаписан откатом `sync_repo()` соседнего пайплайна в 12:00:02 (на диске generated_at=10:32, коммитов файла после 10:54 нет). `vps_ai_pipeline` увидел старый hash == hash в meta → `gemini_blocks_need_update()=False` → ни блоков, ни видео. Причина: `generate_ai_analysis.py` писал json без лока и держал его незакоммиченным на время `generate_tts()` (десятки секунд).
2. **Залипший флаг Claude.** `forecast_analysis_claude.json` (от 22.08) имеет `changed: true` навсегда; `check_ai_new_models()` читал его как «Claude обновился» и КАЖДЫЙ разбор очереди гонял `make_blocks_cloud` + `make_video.py` (claude, 6 блоков, ~13 мин) ПЕРЕД Gemini. За это время держится process-лок (тики cron пишут «предыдущий цикл AI ещё выполняется»), растёт окно для откатов, Gemini-блоки стартуют на ~15 мин позже. Генерация Claude отключена сознательно, этот рендер был паразитным.
3. **Hash не изменился.** `_is_fresh()`: если hash (T, осадки, Z500 по дням) тот же и анализ моложе 6 ч — «Данные не изменились, пропускаю» (так было 10:54 UTC). Это штатное поведение, а не баг.

Сопутствующее: очередь `data/_ai_pending_models.json` — tracked-файл, при ручной записи на VPS откатывается тем же `sync_repo()`; edge-tts часто отдаёт «No audio was received» (страницы `_p1` блоков теряются после 3 попыток, видео от этого не страдает).

### Фиксы (04.10, коммиты 9c8cdf0d, 333e7e1c)
- `generate_ai_analysis.py`: `_write_json_and_push()` — json пишется, коммитится и пушится под `/tmp/vps_git.lock` ДО TTS (только на VPS, в Actions/на телефоне поведение прежнее; в git уходят заодно `forecast_days.json`, `verification_snapshots.json`).

### Silero TTS на VPS (07.10.2026)
- Скорость: Silero v4_ru на 2 OCPU A1.Flex ≈ 2–4 с на голос на ~650 символов — быстрее реального времени; RAM хватает с запасом (12 ГБ).
- `pip install torch` на aarch64 по умолчанию тянет CUDA-сборку (2.7 ГБ) — ставить CPU-версию: `pip install torch --index-url https://download.pytorch.org/whl/cpu` (venv `/opt/silero-venv`, `--system-site-packages`).
- `models.silero.ai` с VPS недоступен (таймаут по IPv4). Модель взята из неофициального зеркала HF `Derur/silero-models` (`tts/ru/ru_v4/v4_ru.pt`, 40107184 байт). `picphoto/silero-models_v4_ru` — пустой (только LICENSE/README).
- `.pt` Silero — pickle (`torch.package`), зеркало неофициальное: генерация идёт в песочнице (`unshare -n` + `setpriv` под nobody, без сети, без доступа к токенам); текст готовит и публикует root-код. Если брать Silero в прод — держать ту же схему.
- Токен моста в `/etc/vps-github-bridge/token` — формат `GITHUB_TOKEN=...`, не голый токен.
- `pkill -f`/`pgrep -f` внутри bridge-команды убивает саму команду (в cmdline есть тот же текст) → `returncode -15`; использовать шаблон `[s]ilero` или запускать через отдельный .sh в base64.
- Silero не отдаёт WordBoundary, а `build_text_segments()` строит тайминги предложений (субтитры/кадры) по `boundaries` edge-tts. Для Silero тайминги придётся считать по длительности каждого предложения (озвучивать по предложениям и склеивать) — иначе рассинхрон текста и звука.
- Silero v4_ru: числа и единицы сам не читает — `preprocess_tts()` обязателен; лицензия модели CC BY-NC-SA (некоммерческая).
- Скрипт пробника: `scripts/tts_samples.py` (режимы prep/silero/publish), результат в `docs/tts_samples/`.
