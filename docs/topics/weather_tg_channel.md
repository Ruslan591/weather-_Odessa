# Telegram-канал с погодой по Одессе (weather_tg_channel)

Запрос пользователя (2026-11-23): запустить канал в Telegram. Публиковать по сути всё, начать с прогноза и сводки по городу.

## Требования (от пользователя)
- Сводка по городу каждый час (опасение: не было бы спама).
- Главное: предупреждения о порывах ветра, об осадках, об аномалиях.
- Сводка по текущей погоде выводится только если наблюдается порыв ветра или осадки; указывать, в каком районе.
- Порог порывов: 8 м/с. Порог осадков: 0,1 мм/ч.
- Ложные срабатывания одного датчика фильтруем сразу (решено: осадки подтверждены, если их показали 2 сводки станции подряд, примерно 10 минут; 2 часа не подходит).
- Осадки: если идут только в одном районе, сообщаем сам факт и район; если по всему городу, указываем, где наиболее интенсивные.
- Сообщение при начале дождя и отдельное при его окончании.
- Если по прогнозу ожидаются осадки: предупреждение с временем до начала по прогнозу и сводка в реальном времени.
- Канал сначала частный (отладка), после отладки делаем публичным.
- Позже: карты и анимации (front_test, спутник), итоги верификации моделей, видео (Gemini).

## Реализовано (2026-11-23)
- Скрипт scripts/weather_tg_channel.py (копия на VPS: /opt/weather-tg/weather_tg_channel.py), cron /etc/cron.d/weather-tg каждые 10 минут, лог /opt/weather-tg/run.log, состояние /opt/weather-tg/state.json.
- Обновление скрипта на VPS: curl -H 'Accept: application/vnd.github.raw' https://api.github.com/repos/ruslan591/weather-_Odessa/contents/scripts/weather_tg_channel.py -o /opt/weather-tg/weather_tg_channel.py (через мост). Пробный запуск без отправки: python3 weather_tg_channel.py --dry; принудительная часовая сводка: --digest.
- Правила: порыв >= 8 м/с (повтор при усилении на 4 м/с, эпизод кончается после 3 опросов без порывов); дождь >= 0,1 мм/ч, начало по 2 сводкам подряд, конец по 3 сухим сводкам подряд (чтобы не мигало); «по всему городу» = дождь в >= 3 районах и в более чем половине работающих станций, тогда показываем 3 самых интенсивных; прогноз Open-Meteo minutely_15, окно 3 часа, шаг >= 0,1 мм; аномалии: давление +-3 гПа за 3 ч, температура +-4 °C за час (медиана по станциям, пороги выбраны Claude, согласовать); почасовая сводка без звука только если есть порыв или дождь.
- Станции без температуры в последней сводке считаются офлайн. 2026-11-23: Центр (IODESA138) и Судостроительная (IODESS41) отдавали только давление.
- Данные WU приходят с задержкой 15-20 минут; порог «станция офлайн» 45 минут.

Текст: «Приближается холодный атмосферный фронт. Минимальное давление X гПа ожидается около HH:MM» + температура/ветер/порывы. Повтор не чаще раза в 8 ч.
- Осадки по Ансамблю: часовые rain (мм/ч), эпизод = подряд часы >= 0,1 мм, конец после 2 сухих часов; в посте: начало, окончание, пик (плато >= 90% максимума), сумма, остаток до конца. Предупреждение «Ожидаются осадки» если начало ближе 3 ч.
- Единый пост (без звука): официальная сводка ГМЦ (SYNOP 33837, scripts/weather_tg_synop.py, источник data/synop_<год>.txt, разбор как в synop.js) + частные станции (диапазон температуры, ветер, давление, влажность, порывы, дождь по районам) + накопленные осадки с начала дождя (по истории сводок WU, не зависит от запуска скрипта) + суточная сумма + прогноз Ансамбля. Выходит при каждом новом сроке ГМЦ (раз в 3 часа, всегда) и в остальные часы раз в час только если есть порыв или дождь.
- Сообщение «Дождь закончился»: время начала и конца по последней мокрой сводке и накопленная сумма (до X мм, в среднем Y мм).

## Правки оформления 2026-11-23 (по скриншотам пользователя)

## Оформление постов (шаблоны и правила)
Код: scripts/weather_tg_channel.py (функции official_lines, private_lines, forecast_block, front_text, rain_text_ongoing, rain_text_upcoming, build_digest). Разметка Telegram HTML, время местное (Киев), десятичная запятая.

Общие правила (требования пользователя):
- Сводки идут без звука, предупреждения со звуком.
- Не писать: номер станции ГМЦ, точку росы, количество частных станций и районов, слово «Ансамбль» (пока просто «Прогноз»), названия по улицам (IODESS41 = «Адмиральский»).
- Писать «наблюдения» (не «срок»), «В момент наблюдения слабый дождь», давление «1001,1 гПа (за 3 ч упало на 3,0 гПа)».
- ГМЦ только в трёхчасовом посте; в остальные часы только частные метеостанции.

1) Трёхчасовой пост (новый срок ГМЦ, всегда):
  📋 Сводка по Одессе, HH:MM
  🏛 Официальная сводка ГМЦ (Одесса), наблюдения HH:MM (HH:MM UTC)
  🌡 T °C · влажность N% · давление P гПа (за 3 ч выросло/упало на X гПа)
  💨 ветер СЗ N м/с, порывы до N м/с · видимость N км
  🌧 В момент наблюдения <явление>; осадки за N ч: X мм.
  (пустая строка)
  📡 Частные метеостанции
  🌡 диапазон °C · 💨 ветер · давление · влажность
  💨 Порывы >= 8 м/с: Район X; Район Y.   (если есть)
  🌧 Дождь по всему городу, сильнее: A x мм/ч, B y мм/ч, C z мм/ч.   (или список районов)
  Дождь идёт с HH:MM: выпало до X мм (Район), в среднем Y мм.
  За сутки (с 00:00): до X мм (Район).
  (пустая строка)
  🔮 Прогноз   (если есть что сказать)
  🌀 Приближается холодный атмосферный фронт. Минимальное давление P гПа ожидается около HH:MM, затем рост.
  Ожидается: понижение температуры на ~N °C (до N °C к HH:MM), ветер повернёт на СЗ, порывы до N м/с около HH:MM.
  ⏱ / 🌧 осадки (см. шаблоны ниже)

2) Часовой пост (HH:00, только если есть порыв или дождь): то же без блока ГМЦ, начинается с «📡 Частные метеостанции».

3) Предупреждения (со звуком):
  💨 Порывы ветра до X м/с / Порывы усилились (повтор при +4 м/с): список «Район X (м/с)», «Ветер СЗ, N м/с.»
  🌧 Дождь по всему городу. Сильнее всего: ... / Начался дождь: Район (x мм/ч). + строка прогноза окончания.
  🌤 Дождь закончился. Шёл с HH:MM до HH:MM. Выпало до X мм (Район), в среднем Y мм.
  ☔ Ожидаются осадки через ~N мин, около HH:MM. + фронт + осадки + «Сейчас: ...»
  🌀 Приближается ... фронт (отдельно, не чаще раза в 8 ч).
  📉 Быстрое падение/рост давления (по наблюдениям, 3 гПа за 3 ч); 🌡 Резкое изменение температуры (4 °C за час).

4) Блок про осадки в прогнозе:
  Идёт дождь: ⏱ По прогнозу осадки закончатся около 21:00; наибольшая интенсивность наблюдалась в HH:MM (или с HH:MM до HH:MM, если период >= 30 мин; «наблюдается сейчас», если пик только что), сейчас ~0,3 мм/ч. Такая интенсивность будет наблюдаться до 16:00 (или «сохранится до конца осадков»); [Усиление до ~X мм/ч ожидается с HH:MM до HH:MM;] до конца ожидается ещё ~1,0 мм.
  Ожидается: 🌧 Осадки: с HH:MM до ~HH:MM; наибольшая интенсивность ~X мм/ч (HH:MM–HH:MM); всего ~Y мм.

Следующий шаг (по просьбе пользователя): «окультурить» визуальную подачу (сейчас оформление простое, «дубоватое»): структура, иконки, разделители, возможно карточка/изображение.

- Идея: не «сводка», а ежедневный выпуск с голосом и ритуалами. Опора на то, чего нет у других: 9 частных станций (разница районов), верификация («вчера обещали X, вышло Y»), рекорды из истории, фронты и анимация.
- Рубрики: Утро (~07:30, карточка дня, что надеть/зонт, цифра дня); Сейчас (3-часовой пост ГМЦ+PWS); Тревога (редко, со звуком: что/где/когда/что делать); Вечер (~21:00, итоги суток, экстремумы, прогноз vs факт, завтра); Неделя (воскресенье, «Мы против моделей», море).
- Анатомия поста: заголовок-хук, одна фраза простым языком, карточка, блок «Для профи» в раскрывающейся цитате (blockquote expandable), хэштеги рубрик, закреплённый пост-путеводитель.
- Цвет рамки/шапки карточки по состоянию: спокойно/внимание/тревога.
- Возврат: ритуал утро/вечер, счётчик точности прогноза, рекорды, опрос «угадай завтра».
- Замечание по шкале: WBGT (ISO 7243) про жару, при 4,6 °C «Комфортно» не информативно; предложено зимой показывать ощущаемую (охлаждение ветром), летом WBGT.
- Пожелания пользователя в той же реплике: ощущаемая температура на карточке PWS (шкала как на pws.html); в карточку ГМЦ добавить облачность, видимость, явления (в плитку или текстом ниже).

## Утренний выпуск и вечерние итоги (2026-11-24)
- Решения: утро в 07:00 (не 07:30), вечер в 21:00 по Киеву; выпуски без звука (ISSUE_SILENT); порядок работ: сначала выпуски, потом карточки (ощущаемая в PWS, облачность/видимость/явления в ГМЦ), затем остальное.
- Реализация: scripts/weather_tg_issue.py (morning|evening, флаги --dry, --force), задеплоен в /opt/weather-tg. Прогноз по Ансамблю, наблюдения по 9 станциям, состояние в /opt/weather-tg/issue_state.json (утренний прогноз максимума сравнивается вечером с фактом, ошибка за 7 дней).
- Cron: строки в /etc/cron.d/weather-tg добавлены ЗАКОММЕНТИРОВАННЫМИ (UTC 4,5 и 18,19; скрипт сам проверяет местный час). Включить после одобрения образца. При включении переписать строки без обратных слэшей.
- Технические детали: порыв-одиночка (>1,6 раза выше следующей станции) отбрасывается; в «Для профи» используется <blockquote expandable>; VPS в UTC.
- Открыто: рекорды из истории; опрос «угадай завтра»; недельный выпуск «Мы против моделей»; карточка к выпускам; живой тест после одобрения.

## Gemini пишет текст выпусков (2026-11-24)
- Решение пользователя: шаблонный текст «как план, а не статья», публицистику доверяем Gemini (опыт: video/AI-анализ в основном пайплайне).
- Схема (scripts/weather_tg_issue.py): скрипт считает факты и шаблон; Gemini получает сводку и пишет headline + body (JSON, роль шеф-редактора, STYLE); блок «Для профи» вставляется скриптом без правок. Ключ GEMINI_API_KEY читается из /opt/weather-pipeline/repo/.env, цепочка моделей как в generate_ai_analysis.py (3.7 → 3.5 → 3.8 → 2.5 flash).
- Проверка (урок видео с перепутанными датами): все числа в тексте должны быть в сводке; чужие дни недели, слова «ансамбл/модел/станци», время словами («к четырём часам»), лишние HTML-теги, длина >1100 знаков отклоняются; 1 повтор с указанием ошибок, затем откат на шаблон. Последние 8 заголовков передаются в промпт, чтобы не повторяться.
- Флаги: --dry (печать без отправки), --no-ai (только шаблон), --force (игнорировать час). Лог: run.log строки «issue:».
- Находки: Gemini склонен выдумывать образные «действия» районов и словами писать время (добавлено в запреты); сначала отвечает 3.5-flash (3.7 не отвечает/пропускает).
- Cron всё ещё закомментирован; ждёт одобрения образцов.
