# Telegram-канал с погодой по Одессе (weather_tg_channel)

Запрос пользователя (2026-11-23): запустить канал в Telegram. Публиковать по сути всё, начать с прогноза и сводки по городу.

## Требования (от пользователя)
- Сводка по городу каждый час (опасение: не было бы спама).
- Главное: предупреждения о порывах ветра, об осадках, об аномалиях.
- Сводка по текущей погоде выводится только если наблюдается порыв ветра или осадки; указывать, в каком районе.
- Порог порывов: 8 м/с. Порог осадков: 0,1 мм/ч.
- Ложные срабатывания одного датчика фильтруем сразу (решено: осадки подтверждены, если их показали 2 сводки станции подряд, примерно 10 минут; 2 часа не подходит).
- Осадки: если идут только в одном районе, сообщаем сам факт и район; если по всему городу, указываем, где наиболее интенсивные.
- Сообщение при начале дождя и отдельное при его окончании.
- Если по прогнозу ожидаются осадки: предупреждение с временем до начала по прогнозу и сводка в реальном времени.
- Канал сначала частный (отладка), после отладки делаем публичным.
- Позже: карты и анимации (front_test, спутник), итоги верификации моделей, видео (Gemini).

## Реализовано (2026-11-23)
- Скрипт scripts/weather_tg_channel.py (копия на VPS: /opt/weather-tg/weather_tg_channel.py), cron /etc/cron.d/weather-tg каждые 10 минут, лог /opt/weather-tg/run.log, состояние /opt/weather-tg/state.json.
- Обновление скрипта на VPS: curl -H 'Accept: application/vnd.github.raw' https://api.github.com/repos/ruslan591/weather-_Odessa/contents/scripts/weather_tg_channel.py -o /opt/weather-tg/weather_tg_channel.py (через мост). Пробный запуск без отправки: python3 weather_tg_channel.py --dry; принудительная часовая сводка: --digest.
- Правила: порыв >= 8 м/с (повтор при усилении на 4 м/с, эпизод кончается после 3 опросов без порывов); дождь >= 0,1 мм/ч, начало по 2 сводкам подряд, конец по 3 сухим сводкам подряд (чтобы не мигало); «по всему городу» = дождь в >= 3 районах и в более чем половине работающих станций, тогда показываем 3 самых интенсивных; прогноз Open-Meteo minutely_15, окно 3 часа, шаг >= 0,1 мм; аномалии: давление +-3 гПа за 3 ч, температура +-4 °C за час (медиана по станциям, пороги выбраны Claude, согласовать); почасовая сводка без звука только если есть порыв или дождь.
- Станции без температуры в последней сводке считаются офлайн. 2026-11-23: Центр (IODESA138) и Судостроительная (IODESS41) отдавали только давление.
- Данные WU приходят с задержкой 15-20 минут; порог «станция офлайн» 45 минут.

## Технические детали (найдено в репо)
- Текущие наблюдения: data/pws_raw.json (hourKey, stationId, temp, pressure, wind, windGust, windDir, humidity, precip), обновляет pws_sync.yml.
- Группы станций: data/pws_groups.json (центр: IODESA138, IODESS44, IODESS16; север: IODESS37, IODESS41, IODESA137; остальные: IODESA139, IODESS31, IKRASN91).
- Готовая логика предупреждений по прогнозу: js/fc-alerts.js (weatherAlerts(hours)); можно портировать на Python для канала.
- Осадки рядом: data/nearby_precip.json; прогноз: data/forecast_days.json.
- Не путать с торговой темой: Telegram уже используется в проекте: docs/topics/telegram_bot.md (торговый бот, отдельная тема) и data/hmcbas_telegram_*.json (вода). Канал погоды ведём как отдельную тему.
- pws_raw.json: одна запись на станцию в час (pws_sync.yml, cron :10, scripts/pws_sync.py). Источник: Weather Underground api.weather.com v2/pws/observations/all/1day (все наблюдения за сутки, шаг ~5-10 мин, есть precipTotal, precipRate, порывы). precip в pws_raw = ptMax-ptMin за час.
- Для канала нужен опрос чаще часа: план опрашивать WU с VPS каждые 10 минут по 9 станциям (~1300 запросов/сутки; в pws_sync.py 2 ключа WU, лимит ~1500/сутки на ключ, плюс ~216 запросов/сутки у pws_sync). Ключи WU лежат в scripts/pws_sync.py в публичном репо; для скрипта канала взять их оттуда в /opt/weather-tg/tg.env, не копируя в репо.
